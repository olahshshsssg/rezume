## 1. Концепция: «Редакция»

Продукт — не «волшебный генератор», а **редакционный стол**.

- **Пользователь — автор.** Он приносит сырой текст о себе.
- **ИИ — редактор.** Он правит текст на глазах: зачёркивает лишнее, вписывает точнее, оставляет пометки на полях с объяснением правки. Автор принимает или отклоняет каждую правку.
- **Резюме — гранка.** Белый лист на столе, который верстается в реальном времени.

Из метафоры следуют все решения ниже: бумага вместо стекла, линейки вместо теней, правка вместо «магии», оглавление вместо прогресс-бара.

**Голос двух шрифтов:**
- **Onest** — голос интерфейса и автора: точный, спокойный.
- **Comic Relief** — голос редактора: рукописные пометки на полях, заголовки разделов, пустые состояния. Это «карандаш» в редакционной системе.

> **Граница:** Comic Relief живёт только в интерфейсе конструктора. В шаблонах резюме, PDF и PNG он **не используется** — там остаются шрифты из SPEC §6.4. Резюме должно выглядеть профессионально при любом вкусе интерфейса.

### 1.1. Принципы

1. **Каждый элемент заслуживает места.** Если элемент можно убрать без потери смысла — убираем.
2. **Типографика вместо декора.** Иерархия создаётся размером, весом и пространством, а не цветными плашками и иконками.
3. **Движение объясняет, а не развлекает.** Любая анимация отвечает на вопрос «что изменилось и куда это делось». Выразительность — да, украшательство — нет.
4. **ИИ виден по работе, а не по значкам.** Нет искр, роботов и градиентов. Есть видимая правка текста с объяснением.
5. **Честный текст.** Интерфейс говорит, что делает кнопка, без обещаний и восторгов.

## 2. Кодекс против нейрослопа

Это главный раздел. Каждое правило проверяемо: глазами на ревью или автоматически (§13).

### 2.1. Визуальные клише — запрещено

| Запрещено | Чем заменяем |
|---|---|
| Фиолетовые, сине-розовые, «радужные» градиенты; градиентный текст | Плоские цвета. Градиент не используется нигде, кроме фона-стола (§5.4) |
| Glassmorphism: `backdrop-filter: blur`, полупрозрачные «стеклянные» панели | Непрозрачные поверхности с линейкой в 1 px |
| Свечение (`box-shadow` с цветом акцента, неоновые обводки), «аура» вокруг кнопок | Фокус — сплошное кольцо 2 px (§6.1) |
| Карточки-клоны: сетка одинаковых карточек «иконка + заголовок + 2 строки» | Списки с линейками-разделителями, как в оглавлении журнала |
| Скругления 16–24 px повсюду, «таблетки» везде | Радиусы 0 / 3 / 6 px (§5.3). «Таблетка» — только у тегов навыков |
| Тени на каждом элементе, многослойные мягкие тени | Одна тень в продукте — у листа резюме |
| Blob-фигуры, 3D-иллюстрации, «плавающие» абстракции, сетки из точек на фоне | Никаких иллюстраций. Главный визуал — реальные резюме |
| Стоковые фото улыбающихся людей с ноутбуком | Не используем фотографии людей вообще |
| Бейджи «New», «Beta», «Pro» без причины | Только если за меткой есть реальное условие |
| Счётчики-«социальные доказательства» («10 000+ резюме создано») без данных | Показываем цифры только из реальной аналитики |
| Анимированные бегущие градиентные рамки, shimmer на кнопках | Скелетон без перелива: статичный тон (§8.6) |
| Hero с огромным заголовком по центру + две кнопки + скриншот в «браузерной рамке» | Hero — разворот: слева заголовок, справа живые листы резюме (§11.1) |

### 2.2. ИИ-атрибутика — запрещено

| Запрещено | Чем заменяем |
|---|---|
| Иконка ✨ / искры / звёзды / волшебная палочка | Текстовая кнопка «Отредактировать» или иконка карандаша |
| Слова «ИИ-магия», «волшебство», «умный», «AI-powered» в интерфейсе | «Редактор», «правка», «отредактировать» |
| Роботы, мозги, нейросети, «светящиеся» сферы | Ничего. Редактор не имеет «лица» |
| Эффект печатной машинки «буква за буквой» | Правка блоками: зачёркивание → вписывание (§9) |
| Фиолетовый как «цвет ИИ» | Правки редактора — лазурь (вписано) и кирпичный (зачёркнуто) |
| Спиннер с подписью «ИИ думает…» | Линейка-прогресс под конкретным абзацем + пометка, что именно правится |
| Чат-окно с ИИ | Нет чата. Редактор работает с текстом прямо в документе |

### 2.3. Текстовые клише — запрещено

В интерфейсе, на лендинге, в письмах и уведомлениях.

| Канцелярит | «Осуществите заполнение полей» | «Заполните поля» |

Полный список стоп-слов для автоматической проверки — §13.3.

### 2.4. Эмодзи — запрещено

- Ни одного эмодзи в UI, лендинге, письмах, уведомлениях, toast, пустых состояниях и в именах файлов.
- Замена — иконки Lucide (§7) или просто текст.
- Это касается и SPEC: в макете модалки экспорта (SPEC §5.7) эмодзи заменяются иконками `Monitor`, `Smartphone`, `Image`.

### 2.5. Слоп в сгенерированных резюме — запрещено

Нейрослоп в тексте резюме опаснее, чем в интерфейсе: рекрутеры узнают его сразу. Правила дополняют промпт SPEC §4.3 и проверку SPEC §4.5.

**Запрещённые обороты в ответе ИИ** (добавить в промпт и в пост-проверку как `slop_hits`):

| Язык | Стоп-фразы |
|---|---|
| RU | «в динамичной среде», «высококвалифицированный», «результативный», «играл ключевую роль», «внёс значительный вклад», «широкий спектр», «эффективно», «успешно» (в начале пункта), «с нуля» (без факта), «страстный», «увлечённый своим делом», «нацелен на результат», «командный игрок», «уверенный пользователь ПК», «гибкие навыки», «обладаю», «способствовал», «отвечал за» |
| UZ | «dinamik muhitda», «yuqori malakali», «natijaga yo‘naltirilgan», «jamoaviy o‘yinchi», «muhim rol o‘ynadi», «samarali», «muvaffaqiyatli» |
| EN | «dynamic environment», «results-driven», «passionate», «spearheaded», «leveraged», «synergy», «team player», «go-getter», «detail-oriented», «proven track record», «played a key role», «hit the ground running» |

**Структурные признаки слопа:**
- больше одного тире на пункт;
- конструкция «не только…, но и…»;
- перечисление из трёх прилагательных подряд;
- все пункты одного места работы начинаются одним и тем же глаголом;
- summary начинается с должности + «с N-летним опытом» (разрешено только если N есть во входе);
- одинаковая длина всех пунктов (разброс меньше 15% — признак шаблонности).

**Реакция:** найдено больше 0 стоп-фраз или больше 2 структурных признаков → тот же механизм повтора, что и для выдуманных фактов (SPEC §4.5), с сообщением: «Убери шаблонные обороты: [список]».

### 2.6. Слоп в шаблонах резюме

Решение меняет SPEC §6.2:

| Было в SPEC | Почему слоп | Стало |
|---|---|---|
| Шкалы навыков 1–5 (Creative) | «React — 80%» ничего не значит для рекрутера | Текстовый уровень: «Базовый / Уверенный / Эксперт», только если пользователь его указал |
| Иконки у каждого заголовка секции | Визуальный шум | Только у контактов (телефон, почта, Telegram, сайт) |
| Цветная шапка на всю ширину (Creative) | Допустимо, но без градиента | Плоская заливка `--accent`, без узоров |

## 3. Цвет

### 3.1. Происхождение палитры

**Самаркандская лазурь** — глубокий сине-бирюзовый цвет изразцов Регистана. Используем **цвет, а не орнамент**: никаких узоров, арабесок и «восточных» мотивов в интерфейсе — это превратилось бы в туристический кич.

Нейтральные — тёплые, «бумажные», а не холодно-серые: интерфейс должен ощущаться как стол с бумагой, а не как приборная панель.

### 3.2. Базовая палитра

| Токен | Светлая | Тёмная | Назначение |
|---|---|---|---|
| `--desk` | `#EFECE5` | `#0F1113` | Фон-стол за листом резюме |
| `--paper` | `#F8F6F1` | `#16191C` | Основной фон интерфейса |
| `--surface` | `#FFFFFF` | `#1D2024` | Поля ввода, меню, модальные окна |
| `--ink` | `#1A1C1E` | `#ECE9E3` | Основной текст |
| `--ink-2` | `#55595E` | `#A6A9AD` | Вторичный текст, подписи |
| `--ink-3` | `#8A8E93` | `#6E7277` | Плейсхолдеры, неактивное |
| `--rule` | `#DDD9D0` | `#2C3035` | Линейки, границы |
| `--rule-strong` | `#C4BFB4` | `#3B4046` | Граница поля при наведении |
| `--lazur` | `#12608A` | `#5FB4D4` | Акцент: основные кнопки, ссылки, вписанный редактором текст |
| `--lazur-strong` | `#0B4A6B` | `#86C8E0` | Hover / pressed |
| `--lazur-wash` | `#E3EEF3` | `#152A35` | Фон выделения, вставки редактора |

### 3.3. Правила применения

- **Лазурь — редкий цвет.** На экране одновременно не больше одной залитой лазурью кнопки. Всё остальное — чернила на бумаге.
- **Цвет несёт смысл.** Лазурь = действие и вписанный текст. Кирпичный = удалено или ошибка. Оливковый = принято. Охра = обратите внимание. Ни один из этих цветов не используется «для красоты».
- **Тёмная тема — не инверсия.** Лист резюме в тёмной теме остаётся **белым** (это реальный документ), меняется только стол и интерфейс вокруг.
- **Цветовые темы резюме** (SPEC §6.3) не смешиваются с палитрой интерфейса: превью резюме — отдельный мир со своими цветами.

## 4. Типографика

### 4.1. Гарнитуры

| Роль | Шрифт | Начертания | Подмножества | Источник |
|---|---|---|---|---|
| Интерфейс, формы, основной текст | **Onest** | Variable 400–700 | cyrillic, latin, latin-ext | `@fontsource-variable/onest` |
| Голос редактора: заголовки разделов, пометки на полях, пустые состояния, лендинг | **Comic Relief** | 400, 700 | cyrillic, latin, latin-ext | `@fontsource/comic-relief` |

**Почему Onest:** гротеск, спроектированный с учётом кириллицы, с характером, но без претензии. Не Inter и не Roboto — их узнают как «шаблон по умолчанию». Табличные цифры (`tnum`) для дат и счётчиков.

**Правила для Comic Relief:**
- Курсива нет → `font-synthesis: none`, чтобы браузер не рисовал ложный наклон. Акцент внутри текста — только весом 700.
- Никогда в мелком служебном тексте меньше 15 px — теряет читаемость.
- Никогда в полях ввода, кнопках, таблицах и навигации — это голос редактора, не элементы управления.
- Проверить узбекский апостроф: `‘` (U+2018) и `ʻ` (U+02BB). Если `ʻ` отсутствует, при отображении заменять на `‘` (функция `normalizeUzApostrophe`).

### 4.2. Шкала (ПК, базовый 16 px)

| Токен | Шрифт | Размер / межстрочный | Вес | Трекинг | Где |
|---|---|---|---|---|---|

| `h1` | Comic Relief | 36 / 42 | 700 | −0.005em | Заголовок шага |
| `h2` | Comic Relief | 24 / 30 | 700 | 0 | Подразделы, модальные окна |
| `h3` | Onest | 18 / 26 | 600 | 0 | Заголовки карточек опыта |
| `body` | Onest | 16 / 26 | 400 | 0 | Основной текст, подсказки |
| `body-s` | Onest | 14 / 22 | 400 | 0 | Подписи полей, вторичный текст |
| `label` | Onest | 13 / 18 | 500 | 0.02em | Метки над полями (без капса) |
| `caption` | Onest | 12 / 16 | 500 | 0.03em | Счётчики, номера шагов, `tnum` |
| `note` | Comic Relief | 15 / 22 | 400 | 0 | Пометки редактора на полях |

**Мобильная шкала:** `display` 40/44, `h1` 28/34, `h2` 20/26; остальное без изменений.

### 4.3. Правила набора

- Длина строки текста — не больше 68 знаков (`max-width: 68ch`).
- Капс не используется. Метки — строчными с лёгким трекингом.
- Кавычки «ёлочки», внутренние „лапки“; длинное тире с неразрывным пробелом перед ним; `ё` не заменяется на `е`.
- Висячие предлоги: неразрывный пробел после однобуквенных и двухбуквенных предлогов и союзов (функция `typograf` из `packages/shared` для всех строк i18n).
- Числа и даты — `font-variant-numeric: tabular-nums`.

## 6. Компоненты

### 6.1. Фокус и состояния

- Фокус: `outline: 2px solid var(--lazur); outline-offset: 2px;` только на `:focus-visible`.
- Hover: меняется цвет или граница, **никогда не размер** (без `scale` у кнопок).
- Disabled: `--ink-3`, без прозрачности всего элемента, курсор `not-allowed`, причина в подсказке.

### 6.2. Кнопки

| Тип | Вид | Когда |
|---|---|---|
| Основная | Заливка `--lazur`, текст `#FFF` (тёмная тема — `#0F1113`), высота 40, отступы 0 16 | Одно главное действие на экране |
| Вторичная | Граница 1 px `--rule-strong`, текст `--ink` | Остальные действия |
| Текстовая | Текст `--lazur`, подчёркивание появляется при hover (анимация §8.3) | Ссылки, «Добавить место работы» |
| Опасная | Текст `--brick`, без заливки | «Удалить» |

Текст кнопок — глагол в инфинитиве, без иконки, если смысл и так ясен: «Скачать», «Отредактировать», «Добавить место работы».

### 6.3. Поля ввода

- Высота 44, фон `--surface`, граница 1 px `--rule`, радиус 3.
- Метка над полем (`label`), подсказка под полем (`body-s`, `--ink-2`). Плейсхолдер — пример значения, не повтор метки: метка «Компания», плейсхолдер «Saber Publisher».
- Ошибка: граница `--brick`, текст ошибки под полем, без иконки-восклицания.
- Многострочное поле опыта: растёт по содержимому, справа внизу — счётчик `caption` «412 / 1500».

### 6.4. Оглавление (навигация по шагам)

Вместо прогресс-бара и «таблеток» шагов — оглавление, как в журнале:

```
Содержание
───────────────────────────
Личные данные ............ 1   ✓
Контакты ................. 2   ✓
Опыт ..................... 3   2 записи
Образование .............. 4
Навыки ................... 5
Вид ...................... 6
───────────────────────────
```

- Отточия — CSS (`border-bottom: 1px dotted` в flex-заполнителе).
- Текущий шаг: текст `--ink`, вес 600, слева линейка 2 px `--lazur`.
- Статус справа (`caption`): «✓» как символ шрифта Onest, а не эмодзи; «2 записи»; «нужно исправить» — `--brick`.

### 6.5. Записи опыта и образования

Не карточки с тенью, а **записи**, разделённые линейкой:

```
──────────────────────────────────────────────
TeamLead · Saber Publisher             ⋮⋮  ⌄
март 2022 — по настоящее время
──────────────────────────────────────────────
```

- Свёрнутая запись: должность и компания (`h3`), период (`body-s`, `tnum`).
- Ручка перетаскивания `⋮⋮` (иконка `GripVertical`) появляется при наведении.
- Развёрнутая: поля формы с отступом слева 16 px.

### 6.6. Теги навыков

- Высота 28, `radius-pill`, граница 1 px `--rule`, текст `body-s`.
- Hover — граница `--rule-strong`, появляется крестик удаления.
- Блоки Hard / Soft / Языки — подписаны `label`, без цветового кодирования тегов.

### 6.7. Выбор шаблона

Шаблоны — уменьшенные листы **с данными пользователя** (не lorem ipsum), в ряд, с подписью под каждым. Выбранный приподнят (тень поднятого листа) и подписан `--ink` весом 600. Никаких рамок-обводок вокруг выбранного.

### 6.8. Выбор цветовой темы резюме

- 8 квадратных образцов 32×32, `radius-1`, через 8 px. Квадраты — тихая отсылка к изразцам, без орнамента.
- Выбранный: внутренняя обводка 2 px `--paper` + внешняя 2 px `--ink` (читается в обеих темах).
- Девятый элемент — «Свой цвет»: квадрат с границей пунктиром, открывает color picker.

### 6.9. Toast

- Внизу слева, ширина до 400, фон `--ink`, текст `--paper`, радиус 3.
- Текст — что произошло, без восклицаний: «Запись удалена». Справа текстовая кнопка «Вернуть».
- Висит 5 с, при наведении таймер останавливается.

### 6.10. Индикатор сохранения

Справа в верхней строке, `caption`, `--ink-2`:
- «Сохранено» → при вводе «Сохраняется…» → «Сохранено в 15:42».
- Нет сети: «Нет сети. Изменения сохранятся на этом устройстве» (`--ochre`).

## 8. Движение

Ответ на вопрос 6 — **выразительно**. Но выразительность здесь означает **физику бумаги и вёрстки**: листы ложатся, блоки переверстываются, чернила проступают. Никаких отскоков, мерцания и «праздничных» эффектов.

### 8.1. Токены

| Токен | Длительность | Где |
|---|---|---|
| `dur-instant` | 80 ms | Hover, нажатие |
| `dur-quick` | 160 ms | Появление подсказок, меню, смена иконки |
| `dur-base` | 240 ms | Переходы между шагами, раскрытие записей |
| `dur-expressive` | 420 ms | Переверстка при смене шаблона, вклеивание фото |
| `dur-sheet` | 600 ms | Крупные движения листа: появление, переход ПК ↔ телефон |

| Кривая | Значение | Где |
|---|---|---|
| `ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | По умолчанию |
| `ease-enter` | `cubic-bezier(0, 0, 0, 1)` | Появление |
| `ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | Исчезновение (короче появления на 30%) |
| `spring-paper` | Motion: `{ type: 'spring', stiffness: 260, damping: 32, mass: 1 }` | Лист и записи: мягкая остановка без отскока |

`spring-paper` подобран так, чтобы перелёт был не больше 1–2 px: лист «ложится», а не прыгает.

### 8.2. Инструменты

- **Motion** (`motion/react`) — layout-анимации (FLIP), `layoutId`, `AnimatePresence`, жесты перетаскивания.
- **CSS-переходы** — hover, цвет, фокус.
- **View Transitions API** — переход между страницами «Главная → Редактор» (с откатом на простое появление, где API нет).
- Анимируются только `transform`, `opacity`, `clip-path`, цвет. Никогда `width`, `height`, `top`, `left` напрямую (для высоты — Motion `layout`).

### 8.3. Микровзаимодействия

| Элемент | Поведение |
|---|---|
| Основная кнопка | Hover: фон → `--lazur-strong` за `dur-instant`. Нажатие: `translateY(1px)`. Без scale |
| Текстовая кнопка | Подчёркивание «прорисовывается» слева направо: `background-size` 0 → 100% за `dur-quick` |
| Поле ввода | Фокус: граница → `--lazur` за `dur-instant`; метка не «уплывает» (никаких floating labels) |
| Чекбокс | Галочка рисуется `stroke-dashoffset` за `dur-quick` |
| Тег навыка | Добавление: появляется на месте ввода и «въезжает» в ряд (layout). Удаление: схлопывается, соседи сдвигаются |
| Оглавление | При переходе шаг-маркер (линейка 2 px) скользит к новому пункту (`layoutId="toc-marker"`) |
| Сохранение | «Сохраняется…» → «Сохранено» сменяется вертикальным сдвигом текста на 4 px, без иконок-галочек |

### 8.4. Переходы

| Переход | Анимация |
|---|---|
| **Главная → Редактор** | Лист-пример на лендинге увеличивается и ложится на стол редактора (View Transition, `dur-sheet`) |
| **Шаг → шаг** | Форма уходит на 24 px в сторону движения с исчезновением (`dur-base`, `ease-exit`), новая приходит с противоположной стороны. Направление учитывает порядок шагов |
| **Раскрытие записи** | Высота через Motion `layout`, содержимое появляется с задержкой 60 ms |
| **Добавление записи** | Новая запись разворачивается, слева на 1.2 с остаётся линейка `--lazur`, затем гаснет — глаз находит новое |
| **Удаление записи** | Запись схлопывается (`dur-base`), соседние подтягиваются; toast «Запись удалена · Вернуть». При возврате — обратное движение на то же место |
| **Перетаскивание записи** | Поднятая запись получает тень поднятого листа и наклон 0.6°; при отпускании ложится через `spring-paper` |
| **Модальное окно** | Затемнение `dur-quick`; окно поднимается на 8 px + проявляется (`dur-base`). Закрытие быстрее на 30% |
| **Светлая ↔ тёмная тема** | Перекрёстное проявление 200 ms через View Transition. Без «круга, расходящегося от кнопки» — это клише |

### 8.5. Выразительные моменты (их ровно четыре)

**1. Переверстка при смене шаблона** (`dur-expressive`)

Самый заметный эффект продукта. Каждая секция резюме (шапка, опыт, навыки…) имеет `layoutId`. При смене шаблона:
1. Лист чуть приподнимается (тень поднятого листа, 120 ms).
2. Секции **перелетают** на новые места: из одной колонки в сайдбар и обратно. Задержка между секциями 30 ms, сверху вниз.
3. Типографика (размеры, шрифт) меняется перекрёстным проявлением в середине движения.
4. Лист опускается (`spring-paper`).

Пользователь видит, что данные не потерялись, а просто переложены. Это и есть смысл анимации.

**2. Цвет проступает, как чернила** (смена темы резюме, 360 ms)

Новый акцентный цвет не «щёлкает», а проступает сверху вниз: CSS-переменная меняется у секций по очереди с задержкой 25 ms, у каждой — переход цвета 200 ms. Ощущение: краска впитывается в бумагу.

**3. Вклеивание фото** (`dur-expressive`)

После кропа фото появляется в шапке листа с масштаба 1.04 и поворота −1.5° до 1 и 0° через `spring-paper` — как наклеенная на анкету карточка.

**4. Печать при экспорте** (длительность = реальное время экспорта)

- Над листом проходит тонкая линия `--lazur` сверху вниз — как головка принтера. Её положение отражает реальный прогресс (статусы SPEC §7.1: `queued` → 10%, `processing` → плавно до 90%, `done` → 100%).
- Для мобильной версии лист сначала **сужается до ширины телефона** (FLIP 794 → 390 px, `dur-sheet`), секции переверстываются в одну колонку — пользователь видит, что получит.
- Ошибка экспорта: линия останавливается и становится `--brick`, под листом — текст ошибки и «Повторить».

Больше выразительных моментов не добавляем: если всё анимировано, ничего не выделяется.

### 8.6. Загрузка и ожидание

- **Скелетоны** — статичные блоки цвета `--rule` с радиусом 3. Без shimmer-перелива.
- **Загрузка до 300 ms** — ничего не показываем (без мигания скелетона).
- **Долгие операции** (экспорт, генерация) — конкретный текст, что происходит, а не абстрактный спиннер.

### 8.7. Ограниченное движение

При `prefers-reduced-motion: reduce`:
- все перемещения, масштабы и повороты отключаются;
- остаются только перекрёстные проявления по 120 ms;
- переверстка шаблона → мгновенная смена с проявлением;
- линия печати → текстовый прогресс «Готовим файл… 60%»;
- правка редактора показывается сразу в итоговом состоянии с пометками (§9.5).

В настройках профиля есть переключатель «Меньше движения» — он работает независимо от системной настройки.

### 8.8. Бюджет производительности

- 60 fps на ноутбуке среднего уровня (Chrome, 4× CPU throttling в DevTools — не ниже 45 fps).
- Одновременно анимируется не больше 20 элементов; при большем числе секций задержка между ними сокращается.
- Ввод текста в форме **никогда** не запускает анимаций на листе — превью обновляется мгновенно (SPEC §5.5).

## 9. Редактор (как выглядит работа ИИ)

### 9.1. Название и вход

- Функция называется **«Редактор»**. Кнопка — «Отредактировать» (вторичная, с иконкой `Pencil`). После первой правки — «Отредактировать заново».
- Рядом — выбор тона (SPEC §4.3) обычным выпадающим списком: «Сдержанно / Уверенно / Живее».
- Если данных мало — кнопка неактивна, подсказка: «Редактору нужна должность и хотя бы одно место работы, проект или навыки».

### 9.2. Процесс правки

Правка происходит **прямо в тексте**, который написал пользователь, — на развороте «форма + лист» форма уступает место режиму правки.

```
 ┌─ Опыт · Saber Publisher ─────────────────────────────┬────────────────────────┐
 │                                                      │                        │
 │  ~~руковожу командой из 4 человек, сделали сайт~~    │  перевёл в достижения  │
 │  ~~журнала на next, ускорили загрузку в 3 раза~~     │                        │
 │                                                      │  цифры взяты из        │
 │  · Руководил командой из 4 разработчиков             │  вашего текста         │
 │  · Перевёл сайт журнала на Next.js                   │                        │
 │  · Ускорил загрузку страниц в 3 раза                 │                        │
 │                                                      │                        │
 │  [Принять]  [Оставить мой текст]  [Ещё вариант]      │                        │
 └──────────────────────────────────────────────────────┴────────────────────────┘
    текст: Onest                                          поля: Comic Relief, --ink-2
```

**Хореография для одного блока** (порядок блоков — как приходят SSE-события, SPEC §4.6):

| Шаг | Время | Что происходит |
|---|---|---|
| 1 | 0 ms | Под редактируемым абзацем появляется тонкая линейка `--lazur` и медленно ползёт слева направо — пока ждём событие этого блока. На полях: «Читаю опыт в Saber Publisher» (Comic Relief) |
| 2 | событие пришло | Исходный текст **зачёркивается**: линия `--brick` прорисовывается слева направо по каждой строке (`clip-path`, 200 ms на строку, строки с задержкой 60 ms), текст тускнеет до `--ink-3`, фон `--brick-wash` |
| 3 | +250 ms | Ниже **вписываются** новые пункты: каждый проявляется и сдвигается на 4 px вверх (`dur-base`), задержка 80 ms между пунктами; фон `--lazur-wash` |
| 4 | +200 ms | На полях появляются пометки редактора (§9.3) — проявление с наклоном −1° → 0° |
| 5 | +100 ms | Появляются кнопки решения |
| 6 | Принять | Зачёркнутое схлопывается по высоте, фон вставки гаснет за 400 ms, пометки уходят. Остаётся чистый текст. В оглавлении у шага — «отредактировано» |
| 7 | Оставить мой текст | Обратное движение: вставка схлопывается, зачёркивание стирается справа налево |

Summary и «Сильные стороны» появляются как **вставки** без зачёркивания (исходного текста нет) — пометка на полях: «написал по вашему опыту и навыкам».

### 9.3. Пометки на полях

Пометки объясняют **почему** — в этом главный анти-слоп-эффект: пользователь видит логику, а не «магию».

- Шрифт Comic Relief, 15 px, `--ink-2`; к фрагменту ведёт тонкая линия-выноска 1 px `--rule-strong`.
- Не больше 2 пометок на блок, каждая — до 40 знаков.
- Формулирует сервер по результату правки (детерминированно, без отдельного запроса к ИИ):

| Условие | Пометка |
|---|---|
| Обязанности → глаголы действия | «перевёл в достижения» |
| Есть числа | «цифры взяты из вашего текста» |
| Нормализованы названия технологий | «уточнил названия: next → Next.js» |
| Удалены клише из исходного текста | «убрал общие слова» |
| Исходный текст был короче 80 знаков | «мало деталей — добавьте результат» (`--ochre`) |
| Сработала проверка фактов и пункт удалён (SPEC §4.5) | «убрал пункт, которого нет в ваших данных» |

Требование к SPEC: в SSE-событие `experience` добавить поле `notes: string[]` (коды пометок; текст — из i18n).

### 9.4. Сравнение

Переключатель «Ваш текст / Правка» над блоком. В режиме сравнения — классическая корректура: удалённые слова зачёркнуты `--brick`, добавленные подчёркнуты `--lazur` (дифф по словам, SPEC §5.6).

### 9.5. Ограниченное движение и ошибки

- `prefers-reduced-motion`: блок сразу показывается в итоговом состоянии шага 4 (зачёркнуто + вписано + пометки), без анимации.
- Ошибка редактора: линейка-прогресс становится `--brick` и останавливается, на полях: «Не получилось. Попробуйте ещё раз или оставьте свой текст». Форма остаётся рабочей.
- Лимит исчерпан: кнопка неактивна, подпись: «Правок на сегодня больше нет. Завтра снова будет 20».

## 10. Голос и тексты

### 10.1. Правила

- На «вы», «вы» — со строчной.
- Короткие предложения. Одна мысль — одно предложение.
- Кнопка говорит, что произойдёт: «Скачать PDF», не «Продолжить».
- Ошибка говорит, что случилось и что делать: «Фото больше 5 МБ. Выберите файл поменьше».
- Без восклицательных знаков, риторических вопросов, эмодзи (§2).

### 10.2. Ключевые тексты

| Место | Текст |
|---|---|
| Лендинг, заголовок | «Резюме, которое не стыдно отправить» |
| Лендинг, подзаголовок | «Напишите о своём опыте как получится. Редактор переформулирует текст, а вы решите, что оставить» |
| Лендинг, кнопка | «Начать» |
| Лендинг, примечание | «Без регистрации. Регистрация нужна, только чтобы открыть резюме с другого устройства» |
| Шаг «Опыт», подсказка к полю | «Пишите своими словами: что делали, что получилось. Цифры, если есть» |
| «Нет опыта работы» | «Опыта работы пока нет — расскажите об учебных проектах и стажировках» |
| Пустой список навыков | «Начните вводить навык, например React или Excel» |
| Перед первой правкой (поля, Comic Relief) | «Когда заполните опыт, я помогу его сформулировать» |
| Модалка экспорта, заголовок | «Скачать резюме» |
| Варианты экспорта | «Для компьютера — PDF, A4» · «Для телефона — PDF, одна страница» · «Картинка — PNG для мессенджеров» |
| Проверка перед скачиванием | «Есть 2 замечания. Можно скачать и так» |
| Экспорт готов | «Файл готов» (и скачивание начинается автоматически) |
| Ошибка сети | «Нет связи с сервером. Изменения сохранены на этом устройстве» |
| 404 | «Такой страницы нет. Вернуться к резюме» |

### 10.3. Узбекский и английский

Те же правила. Узбекский — латиница, апостроф `‘` в `o‘`, `g‘`; на «Siz». Английский — sentence case в кнопках и заголовках («Download PDF», не «Download Pdf»).

### 11.4. Телефон

ПК первым, но телефон должен работать полноценно (PRD §6):
- Верхняя строка: имя резюме, индикатор сохранения, «Скачать».
- Оглавление — выпадающий список под верхней строкой: «3 · Опыт ▾».

- Переверстка шаблона и «печать» сохраняются; перетаскивание записей — по долгому нажатию.

## 12. Доступность

- WCAG 2.1 AA (PRD §6); все пары цветов проверены (§3.2).
- Каждое выразительное движение имеет вариант для `prefers-reduced-motion` (§8.7).
- Правка редактора озвучивается: `aria-live="polite"` — «Редактор изменил опыт в Saber Publisher: 3 пункта. Принять или оставить свой текст».
- Зачёркнутый текст: `<del>`, вписанный: `<ins>` — экранные дикторы читают корректно.
- Comic Relief не используется в элементах управления (§4.1), поэтому читаемость форм не страдает.
- Минимальная зона нажатия — 44×44 px на телефоне, 32×32 на ПК.
- Порядок фокуса совпадает с визуальным; модальные окна держат фокус внутри.
